# Oriel 插件开发

完成插件与宿主之间的接入或审查。项目约束与 skill 维护规则统一遵循根目录 [AGENTS.md](../../../AGENTS.md)。

## 按任务查阅

先查[当前设计基线](../../../docs/design/current-design.md)的相关边界，再按本次改动选择规范；不要求读取全部文档。

| 本次工作 | 主要入口与关注点 |
| --- | --- |
| 目录发现、插件声明、页面展示、随包说明 | [网页接入规范](../../../docs/design/web-page-plugins.md)：字段、目录边界、展示方式和配置兼容 |
| 本地服务与规则引用 | [本地服务规范](../../../docs/design/local-services.md)：就绪核验、公共动作、实例归属和退出清理 |
| 每网页前置程序 | [网页前置程序规范](../../../docs/design/web-page-preparation.md)：执行上下文、结果、页面加载、进程归属和旧接入兼容 |
| 交付命令、新能力或配置归属 | 当前设计基线的交付、生命周期、配置与待定范围；区分已有契约与尚未确认的能力 |

纯插件业务修改使用插件自身的开发约定和文档；涉及 UI 或设计方向变更时，按根目录规则选用对应 skill。

## 接入流程

- 检查相关声明、配置、公开接口与现有代码，确定改动位于工具业务、适配层还是宿主管理层；具体工具的业务规则留在其自身仓库或模块。
- 按所选规范完成实现或审查，检查受影响的默认值、用户覆盖和设备绑定；协议细节、版本兼容及阶段状态以正式规范和基线为准。
- 按规范中的验证入口检查受影响行为，覆盖相关的配置校验、失败状态或生命周期边界；说明实际验证结果与平台缺口。
