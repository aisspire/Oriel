# Oriel 插件开发

## 目标与入口

在保持独立工具可单独使用的前提下，完成符合 Oriel 管理边界的接入。遵守根目录 [AGENTS.md](../../../AGENTS.md)，按任务阅读[当前设计基线](../../../docs/design/current-design.md)中的交付、生命周期、页面、配置与分层章节。

## 当前可用指导

- 先查看现有代码、配置及接口，区分工具业务、适配层与宿主管理职责。兼容插件接入应无需重新编译宿主，适配可以位于 Oriel 或工具侧。
- 按工具需要声明获取、安装、更新、启动、停止等能力或配置命令，不要求每个工具提供全部步骤，不因存在脚本就直接执行。
- 保留原有页面、终端或独立适配页面的选择，页面显示不决定后台运行；导航排序不决定启动顺序。
- 区分受管理进程和仅连接的外部服务，明确生命周期能力、操作结果与失败状态；进程启动不直接等于业务就绪。
- 配置以 Oriel 本地配置为权威，独立工具的业务数据及自身配置继续由工具负责。按改动检查默认值、用户覆盖和设备绑定的归属。
- 根据任务完成必要实现或审查，并验证实际受影响的行为；仅设计请求不自动转为编码，平台未验证部分明确说明。

## 暂未确定的部分

通信协议、配置字段、脚本输入输出、终端与页面装载技术尚未定案。本 skill 暂不规定模板或具体命令，后续依据已确认规范与真实接入逐步补充，不把本次实现选择自动固化为统一规范。

## 冲突与维护

发现本 skill 与用户要求、已确认设计或代码冲突，或出现值得复用的流程补充时，指出条目、依据与建议，询问用户是否更新本 skill；确认前不自行修改。已明确授权的 skill 更新无需重复询问。

继续无冲突且已授权的工作，影响当前任务正确性的冲突只澄清相关部分。共享 UI skill 不修改；涉及界面时按根目录规则使用它，Oriel 专属差异留在本地文档与规则。
