# Oriel 设计维护

让当前设计反映最新已确认方向，保留背景和取舍。项目约束与 skill 维护规则统一遵循根目录 [AGENTS.md](../../../AGENTS.md)。

## 按需查阅

- [当前设计基线](../../../docs/design/current-design.md)：查阅本次涉及的方向、边界与延后事项。
- [设计讨论](../../../docs/design/workspace-and-plugins.md)：查阅必要背景并按日期补充记录。
- [文档导航](../../../docs/README.md)：定位愿景、规范或历史资料。

## 维护流程

- 对照当前基线，识别本次新增、替代、确认与延后的结论，区分设计要求、实现状态和本轮验证。
- 更新基线和受影响的专题，移除被替代的当前结论；在决策记录中保留确认日期、变化原因与必要取舍。愿景与导航仅在受影响时同步。
- 检查受影响文档的一致性与本地链接，说明已确认内容、建议与延后事项。

产品或接口内容维护在正式文档中；仅流程本身变化时考虑更新 skill。
