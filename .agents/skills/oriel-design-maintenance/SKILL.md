# Oriel 设计维护

## 目标与入口

让当前设计反映最新已确认方向，保留背景和取舍。遵守项目根目录的 [AGENTS.md](../../../AGENTS.md)。

- [当前设计基线](../../../docs/design/current-design.md)：查阅本次涉及的方向、边界与延后事项。
- [设计讨论](../../../docs/design/workspace-and-plugins.md)：查阅必要背景并按日期补充记录。
- [文档导航](../../../docs/README.md)：定位愿景、规范或历史资料。

## 工作方式

- 从用户本轮要求识别新增、替代、确认与延后的结论；仅讨论的建议保留建议状态，实质歧义需要澄清。
- 更新当前基线的对应内容，再按需要同步愿景与导航；在讨论记录中保留变化原因，不只追加会话而保留过期结论。
- 历史资料保留来源意义，不改写为当前已实现；被新结论替代的问题不继续作为待定事项反复询问。
- 不因维护设计文档而扩大实现范围、运行工具脚本或提前决定用户延后的技术。
- 检查受影响文档的一致性与本地链接，说明本次记录的确认内容和仍延后的事项。

## 冲突与维护

发现本 skill 与用户要求、已确认设计或实际情况冲突，或有可复用的流程补充时，说明具体修改建议，询问用户是否更新本 skill；确认前不自行修改。用户已明确要求的更新无需重复询问。

继续无冲突且已授权的工作，当前任务遵循用户明确要求。共享 UI skill 不在此维护范围。仅有产品设计内容变化时，更新设计文档，不复制整份设计到 skill。
