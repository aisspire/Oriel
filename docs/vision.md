# Oriel 的核心理念

Oriel 是面向个人独立工具的可配置工作台：统一登记、获取、安装、启动、访问和记录，各工具继续独立开发、部署与运行。框架化仅服务 Oriel 自身及其插件开发，暂不面向第三方构建其他工作台产品。

## 边界

1. 工具保持独立。接入首先靠配置，已有项目无需迁入 Oriel 仓库。
2. 集成逐步深入。网址、脚本、服务是操作能力，一个工具可以拥有多个操作。
3. 设备按能力提供入口。Windows 本地执行与未来手机的远程访问分别适配。
4. 数据明确归属。Oriel 管理目录、设备绑定、偏好与运行历史；业务数据、代码、凭证由对应工具负责。
5. 操作权与展示权分开。外部页面不因被展示而获得本地执行或文件访问能力。
6. 工作台布局可配置。最左侧导航支持拖拽排序，默认入口可更改；不可用时按顺序回退到第 1 个可用入口，功能不绑定固定位置。
7. 能力可扩展。安装或登记兼容插件无需重新编译 Oriel；值得独立维护的功能可以拥有独立 Git 仓库并独立使用。
8. 配置与规范协作。插件可以提供脚本，Oriel 可以配置获取、安装、更新、启动等独立命令；插件遵循统一生命周期组件的管理规范，同时保留自身的更新、重启和退出特征。
9. 展示方式可选。支持工具原有页面、终端和单独开发的适配页面；Oriel 可以自带适配，目标工具安装后再启用，工具离开 Oriel 仍能运行。
10. 分层优先。通信协议暂不确定，通过解耦、分层与抽象保留未来提取协议模块的条件，不提前固定传输或 SDK。

## 数据方向

接受联网使用，当前以本地配置作为 Oriel 配置的权威来源。工具业务数据与业务配置继续由对应工具负责。配置存储格式与运行记录存储后续确定，旧 SQLite 方案不自动决定配置权威。同步与服务器共享留待需要时设计，不覆盖当前本地权威的决定；工作目录和解释器路径属于设备绑定，不能直接同步为跨设备通用配置。

## 阶段范围

界面保持简洁，避免过多文字，并支持浅色、深色两套主题。当前先实现无业务功能的首页外壳：单侧边栏、默认首页、Oriel 应用图标与品牌动效。具体插件、管理流程、验证顺序和后续业务交付清单仍待需要时确定。此前最小工作台方案仅作历史参考，具体管理流程按新的插件、页面和生命周期边界重新设计。

具体业务工具不作为当前框架设计的必选任务，留待实际开发时另行设计。浏览器收藏夹、服务器同步、Android、独立密钥管理器和原生外部窗口嵌入同样按需要展开，不提前建立独立 Windows Service。

2026-10-21 已进一步明确：插件交付按需配置，更新和生效按插件特点支持，页面与终端均允许，Oriel 可以自带按需启用的适配。无需重新编译不等于所有插件必须热加载或无需重启。

同日确认启动初版视觉外壳开发，采用浅灰通透的整体外观、窄侧栏、柔和区块及浅粉彩与深墨色的组合。本次具体视觉方案见[首页与视觉设计](design/home-and-identity.md)，不将装饰性区块视为已经接入的业务能力。

原有“已有工具无需迁移项目结构即可使用”的原则继续保留。终端是无页面工具的一种使用方式，内嵌还是外部终端等实现细节后续确定。当前完整边界和延后事项见[当前设计基线](design/current-design.md)。
