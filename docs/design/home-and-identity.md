# Oriel 首页与界面设计

- 更新日期：2026-10-22。
- 范围：应用外壳、默认首页、一级导航、浏览器固定页签二级侧栏及工具应用布局方向。
- 关联：[当前设计基线](current-design.md)、[设计决策记录](workspace-and-plugins.md)。

## 已确认的 UI 原则

- **保持 UI 简洁，避免过多文字。** 围绕页面实际任务保留必要的标题、标签和说明，文字数量按需要取舍，避免用标语、介绍性文案和重复提示填充界面。
- **支持浅色、深色两套主题。**

简洁原则适用于 Oriel 的整体界面设计，不限定为某一页的固定内容清单。

## 当前首页

当前采用单条窄侧边栏和默认首页，主区域展示 Oriel 名称与轻微动效，通过留白形成视觉重点。当前首页的具体呈现是简洁原则的一次应用，后续页面按自身任务组织必要内容。

## 视觉方向

保留浅灰、通透、低对比的整体外观，柔光使用薄荷绿、蜜桃色与雾蓝，深色主题使用深墨色背景。应用图标采用用户提供的新黑白连写设计。

图形、色值、排版与动效可随界面需求继续调整，保持简洁和主题协调。

## 当前范围

当前增加浏览器及自定义网页入口，保留原有首页。网页页采用与无边框窗口控件一体化融合的紧凑工具栏（44px）和原生内容区域，消除冗余空白栏堆叠；Windows 原生恢复无边框窗口边缘拖拽缩放能力。首次启动采用 1100×760 逻辑像素的小窗口，并限制在屏幕工作区内；后续恢复正常关闭前的大小、位置和最大化状态，最小化时保留正常窗口尺寸，显示器变化时调整回可见区域。窗口在恢复完成后显示。代理、网页编辑及密码清除放在操作弹窗中，弹窗打开时隐藏原生网页视图。继续使用现有双主题、字体与图标体系，侧栏长列表独立滚动，小窗口工具栏自适应换行。

用户网页在浏览器内按本地保存的顺序展示，外部插件页面保留一级入口；网页使用本地缓存的网站 Favicon，无图标时回退名称首字，并提供可访问名称。原生网页自身的主题和内容仍由网站决定。具体行为和边界见[网页接入初版](web-page-plugins.md)。

## 浏览器固定页签布局

一级侧栏保留首页与插件入口，浏览器插件内增加可展开、收窄的二级侧栏，承载用户添加的固定页签。浏览器以访问固定网页为目标，不区分常用与普通标签页，不增加收藏区或临时标签列表。

```text
一级导航      浏览器二级侧栏         网页区域
首页          浏览器       收窄      后退／刷新／地址栏／窗口控件
浏览器        图标  工作邮箱         当前网页
其他插件      图标  项目后台
              图标  文档
              ＋ 添加网页
宿主操作
```

一级侧栏底部宿主操作沿用现有实现，本次布局调整集中于浏览器内部。

- 展开时显示图标和名称；收窄时保留图标、选中态及添加、展开操作。悬停提示名称与域名，键盘焦点提供名称及域名的可访问描述；通过菜单键或 Shift+F10 打开操作面板可查看完整信息。明确按钮切换两种状态，保留侧栏状态，不依赖悬停自动展开。
- 默认展开宽度为 240px，可拖动边缘在 200–360px 之间调整，分隔线支持方向键、Home 和 End；收窄为 52px。浏览器可用区域不足 720px 时自动使用图标模式，保留原宽度及展开偏好，空间恢复后还原。
- 页签只有一份列表，不再分上下两个区域；长列表在二级侧栏内独立滚动，添加操作固定在底部。支持拖拽排序，并提供上移／下移作为替代操作。
- 页签名称采用用户设置的名称或别名，页面跳转不自动覆盖；同站点不同账号可通过别名区分。移除入口放在明确菜单操作中，不常驻关闭叉。
- 添加网页登记固定入口，按需创建实例；点击已加载页签回到原状态，不重复创建。切换插件、切换页签、展开和收窄不重建实例。浏览器二级侧栏只在该插件内显示。
- 顶部继续采用一层紧凑浏览工具栏，不新增横向标签栏。二级侧栏通过表面明度、间距和细分隔线表达层级，复用现有浅深主题。

现有网页登记迁移保留稳定 ID、代理和浏览数据目录，不按域名合并账号。页签菜单针对操作目标，不要求先切换网页；图标模式底部保留当前页签的菜单入口，其他页签可通过右键或键盘菜单操作。菜单、管理弹窗与鼠标拖动期间临时隐藏原生网页视图，结束后恢复；不重建实例。空列表只提供添加网页，移除当前项后选择剩余列表首项，没有剩余项时回到浏览器空状态。

固定页签布局阶段已完成 Windows 前端和调试程序构建、核心配置测试及原生交互检查。随后按用户要求仅补齐网站 Favicon：展开与图标模式使用相同图标，按需获取并缓存，失败时回退首字；不扩展自定义图标和原生 Mica、Acrylic。Favicon 本轮按用户要求只编译和打包，不运行测试，不沿用布局阶段结果作为图标行为的验证依据。

## 工具应用布局（已实现）

浏览器负责访问网页，保留地址栏和前进后退等浏览操作；Tether 及后续同类插件使用通用工具应用布局，不显示浏览器地址栏与通用浏览导航。继续使用现有一级插件导航，业务导航与操作由工具页面负责，不为每个工具复制浏览器二级侧栏。

宿主保留必要的窗口拖动、窗口控件及通用管理入口，说明可在插件内部打开；刷新、重试和诊断可按需放入菜单。复用现有浅深主题、字体与紧凑风格，避免重复标题和两层工具栏。使用 WebView 不意味着必须展示浏览器控件，独立桌面外壳并非当前必要条件。

版本 2 网页入口通过 `presentation: "application"` 选择独立应用布局组件，适用于后续兼容工具，不按具体插件 ID 或 URL 写死。省略模式或指定 `browser` 保留原浏览布局，版本 1 保持原语义。应用顶部只放窗口拖动、说明和操作菜单，不额外重复工具品牌标题；菜单提供刷新界面、重试加载、工作台设置及诊断。打开宿主说明或菜单时临时隐藏原生视图，关闭后恢复，说明支持 Escape 与焦点恢复；页面切换不停止后台。设计边界见[当前基线](current-design.md)。
