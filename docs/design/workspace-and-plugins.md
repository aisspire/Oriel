## 2026-10-24：前置程序失败不阻断登记网页

用户明确要求脚本 `PageUrl` 可以省略，并且已有外部转发可用时，不能因本次脚本端口占用或其他失败阻止网页访问。新 `preparation` 改为可选准备：成功有地址时使用返回地址，否则使用登记地址；执行失败有登记地址时仍尝试打开，后台保留失败状态、原因和日志，不虚构程序成功或资源归属。没有登记地址且未取得有效地址时仍报错，旧服务／规则依赖不变。

宿主通过 `ORIEL_PAGE_URL` 向前置程序传递当前登记地址；SSH 模板默认 `PageUrl` 留空，用此上下文检查监听，不必重复填写网址，也不接管外部连接。新增失败结果的运行代次校验，避免旧失败覆盖新结果。完整约定及实际验证见[网页前置程序](web-page-preparation.md)。

## 2026-10-24：重新收敛网页前置程序范围

用户认可先采用每网页可选配置一个前置程序、各页独立执行的最小方向，取得成功／失败与可选页面地址，提供后台执行状态和“重新准备并加载”。不要求持续业务健康检查，不先恢复此前撤回的资源依赖图、动态地址持续更新或通用脚本插件。

用户主动通过程序组合工具或插件的公开接口属于允许的使用方式，不以完全消除工具依赖为目标。插件界面与脚本调用同一公开操作时，由插件自身管理对应业务资源；浏览器及宿主通用流程不理解 SSH 等具体业务。缺少接口或工具时正常报告不可用。每页独立执行不禁止被调用工具复用资源，也不转移外部资源的管理归属。

## 2026-10-20：独立工具与可配置工作台

### 确认结论

- Oriel 统一组织独立工具的登记、运行、访问与必要记录，已有项目保持独立仓库、运行环境和业务数据。

- 能力通过插件式接入扩展，新增兼容插件无需重新编译 Oriel。
- 接入规范与宿主能力允许演进；无需重新编译不等于强制所有插件热加载，也不意味着宿主永远无需升级。

### 理由

独立工具可以持续维护和替换，工作台通过稳定的接入边界组织能力。导航配置与工具身份分离，可以调整界面而不改变工具运行行为。

## 2026-10-21：框架范围、交付与适配

### 确认结论

- 框架只服务 Oriel 及其插件开发，暂不面向第三方构建其他工作台产品。
- 交付方式按插件需求决定。插件可提供脚本，Oriel 可独立配置获取、安装、更新、启动等命令。
- 生命周期由统一组件管理，允许插件声明不同的更新、生效、重启与退出行为。
- 工具可以提供自己的页面；没有页面时可以使用终端；已有页面也可以改用单独适配的页面。
- Oriel 可以自带适配层，在目标工具安装后匹配和启用；工具离开 Oriel 仍保留自身运行方式。
- Oriel 管理的配置以本地配置为权威，独立工具的业务数据与自身配置继续由工具负责。
- 导航有序且可拖拽，默认入口不可用时应回退，并利用排序中的第 1 个可用入口；稳定身份与序号分开。

### 当前整理规则

为衔接“默认入口可更改”和“默认第 1 项”，基线采用未指定时打开第 1 个可用入口、指定入口失效时同样回退的规则，具体 UI 后续细化。

### 理由

不同工具的安装、运行和展示方式差异较大。通用管理组件需要可声明的能力与结果，具体行为留在插件或适配层；本地配置提供明确的编辑来源。

### 明确延后

- 通信协议、配置格式、脚本输入输出及页面和终端装载技术暂不确定，先保持解耦、分层与抽象。
- 监控与端口工具不列入当前规划或验证前置任务，实际开发时另行设计。
- 当时先确定方向；同日后续确认了下文的首页外壳初版范围。首个插件及业务功能交付清单继续延后。

## 2026-10-21：首页外壳与品牌视觉

### 确认结论

- 开始初版开发，范围为单侧边栏、默认首页、应用图标与 Oriel 动效展示。
- 当前不安装或接入任何业务功能、插件或工具，工具区域保持真实空状态。
- 整体采用浅灰通透的外观与窄侧栏，页面使用柔和圆角区块，色彩结合薄荷绿、蜜桃色、雾蓝和深墨色。

### 初版实现方案（后续已调整）

- 沿用 Tauri 2、Rust、Vue 3、TypeScript 与 Vite，前端可以独立运行；桌面外壳不提供宿主命令或插件权限。
- 用四段窗框组成字母 O，作为 Oriel 图标；SVG 原稿同步用于首页、侧栏与平台图标导出。

## 2026-10-21：浏览器二级侧栏与固定页签

### 确认结论

- 浏览器只管理用户主动添加的固定页签，不以完整浏览器为目标，不区分常用与普通标签页，不增加收藏区、临时标签列表或新建标签页流程。
- 一级侧栏负责首页与插件，用户添加的网页放入浏览器插件内的二级侧栏；其他插件的页面继续归各自插件。
- 二级侧栏只有一份固定页签列表，支持展开显示图标与名称、收窄为图标模式、宽度调整及顺序调整；不另设横向标签栏。
- 添加网页即登记固定入口；按需加载，重复点击恢复已有实例。切换插件、页签或侧栏形态不重建实例；返回浏览器时恢复页面与侧栏状态。
- 页签使用稳定身份和用户设置的名称，保留既有代理及独立浏览数据；页面跳转不改写登记名称和起始地址。不常驻普通标签的关闭叉，通过明确操作移除入口。

### 理由与范围

用户需要随时可进入的固定网页，页签数量增长后不宜持续占据一级插件导航。独立二级侧栏为名称、排序和收窄提供空间，同时避免引入收藏管理与临时浏览两套对象。

此前讨论的“常用区＋普通标签区”不再采用，普通临时多标签浏览不属于本次需求。具体布局见[界面设计](home-and-identity.md)。用户随后授权执行修改，采用以下实现。

### 实现与配置

- 宿主通过已有 `browser` 能力类型装载浏览器工作区；用户网页保留原记录和独立数据，外部插件页面保持一级入口。
- 默认侧栏宽度 240px，可在 200–360px 之间拖动或使用键盘调整；图标模式为 52px，空间不足时临时收窄，保留用户偏好。
- 固定页签支持拖拽及上移／下移；排序命令校验 ID 完整集合，拒绝重复、未知或过期列表，不改变当前选择或网页实例。
- `workspace.json` 扩展至版本 2，新增 `browserSidebar`，顺序仍由 `webEntries` 数组保存。版本 1 在内存中迁移，成功写入前保留原文件；错误配置继续阻止覆盖。
- 菜单作用于被操作的页签，移除需明确确认；菜单和调宽期间隐藏原生页面以保证宿主交互，随后恢复。现有网站原生弹窗行为未改为临时标签页。
- 排序使用指针事件并保留键盘替代操作；主 WebView 关闭 Tauri 原生拖放接管，以保证宿主指针交互，未为外部页面增加宿主权限。
- 本轮保留原生密码、代理和权限边界，未运行插件安装、更新或业务工具脚本。

## 2026-10-21：Tether 独立工具与前置资源

### 确认结论

- 独立 SSH 工具命名为 Tether，Windows 首版，以本机 OpenSSH、本地配置和原有 SSH 文件为基础，保留独立运行方式。
- 开发目录设为工作区内 `plugins/external/tether/`，使用独立 Git 仓库；父仓库忽略目录，不作为子模块或宿主源码提交。该位置方便开发，不是发布或运行路径约定。
- 启动只补充缺失转发，已有连接保持运行，同批兼容参数尽量合并。独立关闭单个端口不优先，停止按连接组、主机或全部托管连接处理。
- 外部连接只观测明确可识别内容。登记关联不授予进程管理权，工具只管理自己拥有的连接。
- Oriel 负责生命周期和前置动作调度，Tether 负责内部 SSH、保活与重连。前置转发按稳定规则 ID 请求，已有或正在启动的资源复用，就绪后再打开依赖页面。
- 前置资源保持至本次 Oriel 会话结束，不随页面切换、关闭或加载失败回收。完全退出 Oriel 时停止 Tether 托管转发并取消重连，外部连接不动。
- Windows 生命周期入口采用 `oriel.ps1` 方案；需要托管却缺少有效入口时诊断，不将同名脚本强制用于所有网页或外部服务。

### 理由与实现边界

实际连接由一个管理者负责，稳定规则引用避免重复 SSH 配置和对命令行的猜测。会话级清理适合以启动为主的工作方式，避免为了按页面回收而打断共享连接。

Tether 详细设计和实现交接由其独立仓库维护。该设计讨论时 Oriel 仍只有网页接入能力，生命周期、脚本执行和前置资源尚未实现；候选动作和字段不自动成为已发布协议，该设计轮也不执行插件脚本或真实 SSH。后续最小接入实现见本文末尾记录及[本地服务规范](local-services.md)。

## 仍为建议的事项

同一主线演进宿主与框架、采用短期功能分支、按版本发布预览及在实际复用后提取 SDK，仍属于组织建议，尚未作为必须执行的交付方案。没有因此创建分支、提交、推送或发布软件。
