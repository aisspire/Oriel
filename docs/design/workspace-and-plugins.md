## 2026-10-20：独立工具与可配置工作台

### 确认结论

- Oriel 统一组织独立工具的登记、运行、访问与必要记录，已有项目保持独立仓库、运行环境和业务数据。
- 左侧导航支持拖拽排序，默认入口可调整，UI 与具体功能保持低耦合。
- 能力通过插件式接入扩展，新增兼容插件无需重新编译 Oriel。
- 接入规范与宿主能力允许演进；无需重新编译不等于强制所有插件热加载，也不意味着宿主永远无需升级。

### 理由

独立工具可以持续维护和替换，工作台通过稳定的接入边界组织能力。导航配置与工具身份分离，可以调整界面而不改变工具运行行为。

## 2026-10-21：框架范围、交付与适配

### 确认结论

- 框架只服务 Oriel 及其插件开发，暂不面向第三方构建其他工作台产品。
- 交付方式按插件需求决定。插件可提供脚本，Oriel 可独立配置获取、安装、更新、启动等命令。
- 生命周期由统一组件管理，允许插件声明不同的更新、生效、重启与退出行为。
- 工具可以提供自己的页面；没有页面时可以使用终端；已有页面也可以改用单独适配的页面。
- Oriel 可以自带适配层，在目标工具安装后匹配和启用；工具离开 Oriel 仍保留自身运行方式。
- Oriel 管理的配置以本地配置为权威，独立工具的业务数据与自身配置继续由工具负责。
- 导航有序且可拖拽，默认入口不可用时应回退，并利用排序中的第 1 个可用入口；稳定身份与序号分开。

### 当前整理规则

为衔接“默认入口可更改”和“默认第 1 项”，基线采用未指定时打开第 1 个可用入口、指定入口失效时同样回退的规则，具体 UI 后续细化。

### 理由

不同工具的安装、运行和展示方式差异较大。通用管理组件需要可声明的能力与结果，具体行为留在插件或适配层；本地配置提供明确的编辑来源。

### 明确延后

- 通信协议、配置格式、脚本输入输出及页面和终端装载技术暂不确定，先保持解耦、分层与抽象。
- 监控与端口工具不列入当前规划或验证前置任务，实际开发时另行设计。
- 当前先确定方向，不冻结首版范围、首个插件或交付清单。

- 两个本地 skill 遇到冲突或可复用补充时，先提出具体建议并询问是否更新 skill 本身；明确授权的更新无需重复确认。
- 共享 UI skill 的链接和目标内容不修改。维护询问不阻塞无冲突的已授权工作。

### 理由

长期约束、按任务加载的工作流程和产品设计分别维护。软件运行时的要求仍需落实到配置校验、代码与必要验证。

- 正式文档只链接会纳入仓库的资料，不依赖被忽略的文件或本机专属路径。
- 必要背景整理成正式结论和理由；后续新的正式技术决策、文档图片和项目本地技能不被整目录排除。

### 理由
